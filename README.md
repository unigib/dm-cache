# Cache Lab — CSS45102

An interactive, browser-based direct-mapped cache simulator branded for the University of Gibraltar's CSS45102 course. Open `index.html` in a modern browser; no installation or server is required. Keep `logo.png` alongside `index.html` so the university logo appears in the header.

The simulator has 256 cache lines, four bytes per block, and a 16-bit, byte-addressed memory space of 65,536 bytes. Enter an address in decimal (0–65535), hex (`0x0000`–`0xFFFF`), or binary (`0b` followed by up to 16 bits, or exactly 16 unprefixed binary digits). Unprefixed shorter numbers are decimal. The address preview shows the same value in binary, decimal, and hexadecimal as you type; invalid or incomplete inputs display a dash until corrected. Start a lookup and use **Next step** to request the address, decode its fields, check the tag, fetch a four-byte block on a miss, and deliver the selected byte. This is a staged memory read, not a complete CPU fetch-decode-execute instruction cycle.

The table starts populated: every line is valid, and its six-bit tag is the line number modulo 4. Each block's bytes are read from the matching main-memory addresses. **Restore populated** reloads this state; **Clear cache & restart** resets to invalid lines. Both also reset the CPU, selected example's memory, and statistics. The 1,024-byte cache table scrolls to the accessed line and has a column for each binary offset (`00`, `01`, `10`, `11`). Tags and offsets are binary; data bytes are hexadecimal. The history displays the 12 most recent accesses; statistics include completed cache checks since the last reset.

After clearing the cache, **Show loaded lines only** hides empty lines so newly loaded blocks are easier to find; uncheck it to see all 256 lines. A selected empty line is temporarily shown during a manual lookup. The program's latest-read summary shows whether that read loaded a block or hit an existing one, along with all four bytes and the requested byte. **Recent block fills** records the 12 most recent misses, including their triggering reads, loaded bytes, and any replaced block. Its total includes all misses since reset; pre-populated lines are not counted as fills.

For a reproducible hit/miss demonstration, restore the populated cache and start with `0x0000` (hit). Then access `0x0400` (miss: it maps to the same line with a different tag), followed by `0x0401` (hit in the block just loaded). Cache state persists between lookups. A lookup can be interrupted only by resetting; other inputs and CPU controls are disabled while it is in progress.

Use **Try a program** to run 6502 assembly examples. Each **Next CPU read** fetches one opcode byte, operand byte, or data byte through the same cache, so you can follow every modeled memory request. The listing shows code addresses, real 6502 machine bytes, assembly, and the sample data bytes. The display also shows the program counter (PC), accumulator (A), index registers (X and Y), carry (C), zero (Z), negative (N), and overflow (V) flags. Selecting an example restores the populated cache and resets the CPU and statistics. Manual reads share the same memory and cache but do not advance the CPU.

The **Repeated array scan** program reads 16 neighboring bytes in a loop and repeats the scan three times. Select it, click **Clear cache & restart**, and click **Run next pass** three times: the pass table compares read counts, hits, misses, and estimated time for each pass. Pass counts include CPU instruction and data reads, but exclude the initial `LDY` setup and any manual reads. **Run remaining** completes all remaining passes; individual reads can still be stepped. Reads are bounded by a safety limit when running in bulk.

The illustrative timing model assigns 1 time unit to a hit, 10 total to a miss (lookup and four-byte fill), and 10 to each uncached byte read. Total cached time is `hits × 1 + misses × 10`, and the memory-only comparison is `reads × 10` for the same modeled accesses. The speedup is memory-only time divided by cached time. These are hypothetical memory-access costs, not observed browser time, complete program execution time, or real 6502 cycle counts. Instruction execution, dummy reads, bus timing and other hardware costs are excluded.

The 6502 is an 8-bit CPU with a 16-bit address bus, not a 16-bit CPU. This is a simplified teaching model with a unified instruction/data cache added; a real 6502 does not have a built-in cache. It models the real encodings of `LDA` immediate, absolute and absolute indexed by X; `LDX` and `LDY` immediate; `INX`, `DEY`, `CPX` immediate, `BNE`, `CLC`, and binary-mode `ADC` absolute, with little-endian address operands. Decimal mode is not modeled. Only the example programs are supported: no assembler input, writes, hardware timing, dummy bus cycles, interrupts, or full 6502 emulation. The simulator stops at the end of each listing rather than executing a halt opcode.

The examples load code at `$0200` and the listed data at their shown addresses. Other memory bytes start as their address modulo 256. Data bytes and read values are displayed in two-digit hexadecimal (for example, `0x0A`); cache table address ranges use four-digit hexadecimal with the 6502-style `$` prefix. Mapping calculations use decimal and the address breakdown uses binary. The cache table shows the entire four-byte block loaded on a miss. In the conflict example, code at `$0200` and data at `$0600` map to the same cache line and replace one another.

Memory is byte-addressed. A block maps to exactly one line:

- Block number = floor(address / bytes per block)
- Line index = block number modulo cache lines
- Tag = floor(block number / cache lines)

The 16-bit address is split into a 6-bit tag, an 8-bit line index, and a 2-bit block offset. A valid line with a matching tag is a hit. Otherwise, the accessed block is loaded into that line, replacing its previous block if necessary. From an empty cache, addresses 0, 1024, and 0 are all misses because blocks 0 and 256 map to line 0. For the underlying cache concepts, see David Tarnoff's [cache notes](https://faculty.etsu.edu/TARNOFF/ntes2150/mem_hier/cache.html).
